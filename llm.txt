## 1. PRODUCT OVERVIEW & RESPONSIBILITIES

Alpha Autonomous Client V3 is an autonomous, non-custodial perpetual futures trading terminal engineered to execute high-probability algorithmic trading directly on Decibel DEX (Aptos Mainnet).

### Core Client Responsibilities:
1. **Non-Custodial Move Execution:** Locally signs and dispatches native Aptos Move order transactions directly to Decibel DEX smart contracts using the trader's private key and subaccount.
2. **28-Pair Continuous Confluence Scanning:** Scans all active Decibel perpetual markets in sub-second intervals using a multi-lens confluence engine.
3. **4-Stage Pre-Trade Risk Sentinel:** Enforces directional ban filters, rejection wick trap shields, shadow simulation win-rate floors, and dynamic volatility sizing.
4. **Autonomous Portfolio Harvester:** Actively trails profitable positions, ratchets stops to breakeven at $+1.4R$, locks in $\ge 80\%$ of peak gains, and defends equity with a $\le -3.0\%$ bleed cut.
5. **Sim Lab Intelligence Consumer:** Pairs with Alpha Forge Sim Lab via an encrypted License API Key (`SIM_LAB_TOKEN`), consuming live macro regimes, dynamic maker offsets, and pair cooldowns.
6. **Browser Onboarding Wizard & Dashboard:** Serves an interactive management dashboard at `http://localhost:5050` with an automated 1-minute wallet/subaccount onboarding wizard.

## 4. CLIENT V3 API ENDPOINT SPECIFICATION (PORT 5050)

The Client V3 dashboard and external integrations communicate via an authenticated REST & Server-Sent Events (SSE) interface.

### Dashboard & Health Endpoints:
* `GET /health`:
  - Returns service health, uptime, engine status, and memory consumption.
  - Response: `{ status: "ok", uptime: 3600, version: "3.2.0", engine: "running" }`
* `GET /api/status`:
  - Returns comprehensive trading state: active positions, open orders, 24h PnL, current regime, and license status.
* `GET /api/events` (SSE):
  - Real-time Server-Sent Events stream delivering live ticker prices, order fills, risk vetoes, and harvester updates.

### Configuration & Onboarding Endpoints:
* `GET /api/onboarding/status`:
  - Returns `{ isConfigured: boolean, onboarded: boolean, hasKey: boolean, hasSubaccount: boolean }`.
* `POST /api/onboarding/credentials`:
  - Validates and saves trader Aptos credentials and Decibel subaccount.
  - Automatically queries the Decibel smart contract on-chain to verify primary ownership, delegate permissions, and USDC collateral balance before saving.
* `POST /api/onboarding/complete`:
  - Unlocks the dashboard navigation and boots the trading engine.
* `GET /api/settings`:
  - Returns current client configuration (with sensitive private keys sanitized).
* `POST /api/settings`:
  - Updates trading budget, risk profiles, AI backend selections, and notification webhooks.

### Manual Trading & Emergency Controls:
* `POST /api/trades/close`:
  - Payload: `{ symbol: "BTC-PERP" }`
  - Instantly executes an on-chain market close transaction on Decibel DEX to exit the position.
* `POST /api/system/emergency-stop`:
  - Immediately freezes all engine scanning, cancels all open limit orders, and puts the client into safe standby mode.

## 5. CORE EXECUTION PIPELINE (TRADE LIFECYCLE)

```mermaid
flowchart TD
    Scan["Continuous Confluence Scanner (28 Pairs)"] --> PreTrade{"4-Stage Pre-Trade Risk Sentinel"}
    PreTrade -->|"Pass"| Sizing["Half-Kelly Dynamic Sizing & ATR Stop Calibration"]

    Sizing --> MoveExec["Post-Only Maker Order Signing (Aptos SDK)"]

    Harvester --> BleedCut["Defensive Bleed Cut (<= -3.0%)"]
    Harvester --> Close["On-Chain Settlement & Reserve Sweep"]
```

### Stage 1: Continuous Scanner (`src/engine/standalone-engine.ts`)
* Scans all 28 Decibel markets every cycle.
* Evaluates technical confluence: Trend alignment, RSI, Volume Profile Point of Control (POC), Value Area High/Low (VAH/VAL), and Order Flow CVD.

### Stage 2: 4-Stage Pre-Trade Sentinel (`src/risk/guard.ts`)
* **Gate 1 — Directional Ban Filter:** Automatically rejects setups that oppose the macro market regime.
* **Gate 2 — Rejection Wick Trap Shield:** Detects whale absorption wicks, preventing entries at tops or bottoms.
* **Gate 3 — Counterfactual Paper Veto:** Ingests Sim Lab shadow arena stats; vetoes trades if current win rate $<35\%$.
* **Gate 4 — Dynamic Sizing & Volatility Gate:** Checks spread-to-ATR ratio; contracts sizing to `0.5x` during chop and expands to `1.2x` in high-conviction trends.

### Stage 3: Post-Only Maker Execution (`src/trades/executor.ts`)
* Signs Move transactions locally using `@aptos-labs/ts-sdk`.
* Dispatches orders with `Post-Only` maker enforcement, ensuring zero taker fees and capturing maker rebates.
* Gas Sentry validates that the gas balance is $\ge 0.002\text{ APT}$ before broadcasting.

### Stage 4: Autonomous Portfolio Harvester (`src/risk/portfolio-harvester.ts` - v3.2.0 Dynamic Engine)
* Actively evaluates open positions every 500ms using real-time volatility and volume profile mathematics.
* **Dynamic Volatility Scaling (15m ATR & ADX):** Calibrates take-profit target to market volatility (`1.05x ATR` in chop up to `1.80x ATR` in momentum trends).
* **Volume Profile POC Snapping:** Aligns exit targets with High-Volume Point of Control liquidity nodes where institutional orders accumulate.
* **Capital-Scaled Dynamic Dollar Floor:** Mathematically scales profit hurdle to notional position size (`notional * 0.625%` with $0.25 gas floor), requiring substantive +$1.25 to +$2.80+ net wins instead of micro-penny exits.
* **Strict Logical Conjunction (`&&`):** Enforces that BOTH percentage hurdle AND dollar floor must be met before harvesting.
* **Institutional 0.75% Breakeven Snap:** Once $+1.4R$ is reached, snaps runner stop-loss to entry plus a calibrated `+0.75%` fee cushion—safely above exchange bid-ask spread and noise.
* **Trailing Ratchet:** As price expands, trailing stops ratchet to secure $\ge 80\%$ of peak unrealized profits on runners.
* **Defensive Bleed Cut:** Cuts lagging positions at $\le -3.0\%$ to preserve margin.

## SECTION XXV: PAIR CARD CANDLESTICK RENDERING, DUAL-GRID DOM RESOLUTION & LIVE IN-PLACE ENGINE (2026-10-29)

### 1. Architectural Overview & Problem Context
In both Client V3 (`alpha-autonomouse-client_v3/dashboard/index.html`) and Client V1 (`alpha-autonomouse-client_v1/dashboard/index.html`), market pair cards are rendered in two independent locations:
1. `markets-grid`: Overview dashboard tab (compact preview).
2. `markets-grid-full`: Markets tab (full view).

Previously, each pair card rendered identical DOM IDs (e.g. `mkt-candle-view-${symSafe}`, `mkt-summary-${symSafe}`, `mkt-cvs-${symSafe}`). This caused critical UI failures:
- **Duplicate ID Collisions**: Event listeners (`onMarketTfHover`, `onMarketTfLeave`, `toggleMarketTfPin`) using `document.getElementById` always matched only the *first* (hidden Overview tab) element, rendering clicks and hovers completely inert on the Markets tab (`#tab-markets`).
- **Zero-Dimension Canvas Abort**: Unhiding the candlestick chart (`display: block`) synchronously called `renderAllActiveMarketCandles()` before browser layout reflow, causing `canvas.getBoundingClientRect().width === 0` and silently dropping the render.
- **Cache Data Structure Mismatch**: `renderState()` stored `{ [sym_15m]: klinesArray }` as a raw array, while `getKlines()` expected `{ data: norm, ts }`.
- **Frozen In-Place Indicators**: Polling refreshed prices and 24h stats, but omitted candle indicators (RSI, RVOL, SMC badges, patterns), leaving them frozen on initial values.

### 2. Dual-Grid DOM Resolution & Dimension Fallback
1. **Multi-Element Resolution**:
   All candlestick event handlers and render routines now use `document.querySelectorAll(`[id="..."]`)`:
   ```javascript
   const views = document.querySelectorAll(`[id="mkt-candle-view-${symSafe}"]`);
   const summaries = document.querySelectorAll(`[id="mkt-summary-${symSafe}"]`);
   const canvases = document.querySelectorAll(`[id="mkt-cvs-${symSafe}"]`);
   views.forEach(v => { v.style.display = isPinned ? 'block' : 'none'; });
   ```
2. **Layout-Safe Canvas Sizing**:
   `drawCandlestickCanvas` utilizes defensive bounding checks with container fallbacks:
   ```javascript
   const rect = canvas.getBoundingClientRect();
   const parent = canvas.parentElement;
   const box = canvas.closest('.market-candle-box');
   const width = Math.max(rect.width || (parent ? parent.offsetWidth : 0) || (box ? box.offsetWidth : 0) || 260, 260);
   const height = Math.max(rect.height || (parent ? parent.offsetHeight : 0) || 145, 145);
   ```
3. **Dual Cache Support in `getKlines()`**:
   Supports both `{ data, ts }` objects and raw arrays `Array.isArray(cached)`.
4. **Live In-Place Card Refresh (`updateCardCandleInPlace`)**:
   Runs inside Step 2 of `renderMarkets()` polling loop, dynamically updating RSI, RVOL, 15m pattern, 1h trend, and SMC badges in real-time without redrawing the entire DOM card.
5. **1-Click Card Summary Affordance**:
   Clicking anywhere on the compact summary badge immediately pins/unpins the 15m candlestick chart.

### 1. Problem Statement & Audit Discovery
Following a rigorous third-party architecture and trading risk audit of the Alpha Autonomous execution stack (V3 & V1), 7 critical failure modes were identified that could compromise capital safety or desynchronize state during exchange anomalies or market stress:
1. **Emergency Liquidation Memory Decoupling**: Legacy `closeAllOpenTrades()` simply cleared in-memory tracking arrays without dispatching on-chain market close orders, leaving live exchange positions exposed.
2. **Silent Leverage Configuration Failures & Market Caps**: Leverage setting failures were caught and logged as warnings while execution proceeded. Additionally, DEX-enforced market leverage caps (e.g., 5x on SUI/USD, NEAR/USD vs 40x on BTC/USD) caused silent Move VM aborts (`EINVALID_LEVERAGE(0x1)`) or unexpected on-chain margin levels.
3. **Optimistic Pre-Flight Swallowing**: RPC query failures/timeouts for resting orders and existing positions were swallowed, risking order stacking and duplicate position entry.
4. **Naked Position Risk on Stop Loss Arming Failure**: If post-entry TP/SL placement failed, the bot logged an error but left the open position completely unprotected on the exchange without an active stop loss.
5. **Stop Loss Dollar Ceiling Bypass**: Minimum contract size and minimum margin requirements ($20–$35) overrode the risk parity allocation cap (`Math.max(stratMinMargin, maxSafeAllocForSl)`), exposing small accounts to stop loss hits exceeding the configured $0.85 loss ceiling.
6. **Unauthenticated Control & Liquidation API Endpoints**: Endpoints like `POST /api/positions/close-all`, `POST /api/positions/close`, and `POST /api/control` lacked remote authentication checks when no master password was set, allowing any unauthenticated network actor to mutate bot trading state.
7. **Permissive Public Network Binding**: Server bound to `0.0.0.0` by default, exposing internal APIs directly to LAN/WAN interfaces rather than restricting default access to local loopback (`127.0.0.1`).

### 2. Implementation & On-Chain Move Validation

#### 2.1 On-Chain Move Verification on Decibel DEX (Aptos Mainnet)
Direct query of Decibel perpetual engine view function `perp_engine::market_max_leverage(market)` confirmed tiered leverage caps across asset classes:
- **BTC/USD**: 40x
- **ETH/USD**: 25x
- **SOL/USD**: 20x
- **APT/USD**, **DOGE/USD**: 10x
- **SUI/USD**, **NEAR/USD**: 5x

Simulated entry calls to `perp_positions::configure_user_settings_for_market` confirmed that attempting 10x leverage on a 5x max market (e.g. SUI/USD) strictly aborts Move execution with `EINVALID_LEVERAGE(0x1)`.

#### 2.2 Asymmetric Leverage Gate Policy
To reconcile strategy requirements with DEX contract constraints, an authoritative asymmetric rule was codified across `alpha-autonomouse-client_v3` (`src/trades/executor.ts`) and `alpha-autonomouse-client_v1` (`src/orders/executor.ts`):
- **Bot Requested > DEX Market Maximum**: If the bot requests 10x on SUI/USD, the engine clamps target leverage to the market maximum (5x), logs an informative notice, recalculates margin safely, and proceeds.
- **On-Chain Confirmed > Bot Requested**: If on-chain leverage is higher than the bot's requested risk profile (e.g. account has 10x leverage configured, but bot requests 5x), execution **ABORTS IMMEDIATELY** (`CRITICAL_LEVERAGE_EXCEEDS_REQUEST`).
- **Configuration Failure**: If `mcpClient.setLeverage` fails or is rejected by the RPC, execution fails closed and aborts the trade (`CRITICAL_LEVERAGE_CONFIG_FAILED`).

#### 2.3 Fail-Closed Pre-Flight Verification
All pre-trade queries (`getPositions()`, `getOrders()`) are wrapped in a strict 6-second timeout race (`withTimeout`). Any timeout, network error, or RPC degradation immediately aborts execution (`PRE_FLIGHT_FAIL_CLOSED`), guaranteeing that no order is dispatched without 100% verified order book and position state.

#### 2.4 Concrete Armor & Emergency Unwind Protocol
Post-fill on-chain TP/SL placement operates under a 3-attempt backoff retry loop. If on-chain TP/SL attachment fails after all retries:
1. The engine triggers an immediate emergency market unwind via `mcpClient.closePosition(symbol)` using IOC reduce-only routing.
2. The trade execution result returns `success: false`.
3. The local ledger retains the trade until on-chain verification confirms position size is 0, completely eliminating naked market exposure.

#### 2.5 Absolute Dollar Loss Ceiling Gate ($0.85 Hard Cap)
In `src/risk/guard.ts`, the allocation calculation enforces:
$$\text{MaxSafeAlloc} = \frac{\text{MaxLossPerTradeUsd}}{(\text{BufferedSlDistPct} \times \text{Leverage})}$$
Where `MaxLossPerTradeUsd` is strictly clamped to $\min(\$0.85, \text{Budget} \times 0.03)$.
- If `stratMinMargin > maxSafeAllocForSl`, the trade is **HARD REJECTED** (`🛑 [HARD RISK REJECTION] Minimum margin exceeds safe allocation to guarantee max loss strictly ≤ $0.85`).
- The legacy `Math.max(stratMinMargin, maxSafeAllocForSl)` override is permanently abolished.

#### 2.6 On-Chain Verified Liquidation & Remote Auth Protection
- `POST /api/positions/close-all`: Dispatches IOC reduce-only market close transactions across all open positions, cancels all resting orders, confirms on-chain position size equals 0, and only then releases local margin allocation.
- Remote Authentication Gate: If `ADMIN_PASSWORD` is not configured, state-altering endpoints (`/api/control`, `/api/positions/close`, `/api/positions/close-all`, `/api/trades/reset`) reject all non-loopback requests with `401 Unauthorized`.
- Loopback Binding Default: Server binds to `127.0.0.1` by default unless explicitly overridden via `BIND_ALL_INTERFACES=true` or `HOST=0.0.0.0`.
